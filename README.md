# הזמנות ממייל ← פריוריטי (POC)

הכלי בודק תיבת Gmail כל כמה דקות. הזמנות שמגיעות כ-PDF מצורף מפוענחות, הלקוח והפריטים מזוהים מול פריוריטי, וההזמנה נכנסת לדשבורד.
מהדשבורד בודקים, מתקנים אם צריך ושולחים לפריוריטי. שום הזמנה לא נפתחת בפריוריטי בלי לחיצה.

## התקנה (פעם אחת)
1. Python 3.12 (כבר מותקן במחשב הפיתוח).
2. להעתיק את `config.example.json` ל-`config.json` ולמלא:
   - `gmail.user` – כתובת ה-Gmail.
   - `gmail.appPassword` – **סיסמת אפליקציה** של Google (לא הסיסמה הרגילה): בחשבון Google ← אבטחה ← אימות דו-שלבי (חייב להיות פעיל) ← סיסמאות אפליקציה.
     ב-Gmail ← הגדרות ← העברה ו-POP/IMAP – לוודא ש-IMAP פעיל.
   - `priority.baseUrl` – לדוגמה `https://server/odata/Priority/tabula.ini/COMPANY/`, ו-`user` / `password` של משתמש ה-API
     (עם Personal Access Token: user = הטוקן, password = `PAT`). `appId` / `appKey` – רק אם התקבלו מפריוריטי.
   - `gmail.filter` – חיפוש Gmail נוסף, כדי שרק מיילי הזמנות ייכנסו לדשבורד. לדוגמה `label:orders` (תווית שמסננים אליה ב-Gmail)
     או `subject:הזמנה`. ריק = כל מייל עם PDF.
   - `anthropic.apiKey` – מפתח Claude API (מתחיל ב-`sk-ant-`), לפענוח הזמנות בגוף המייל ו-PDF סרוק. `model` – המודל.
   - `ownCompany` – שם וח.פ של החברה שלנו, כדי שלא יזוהו כלקוח כשהם מופיעים ב-PDF.
3. להפעיל את `start.bat`. הדפדפן ייפתח על http://localhost:8790 (החלון השחור צריך להישאר פתוח).
4. בדשבורד: "רענון נתוני פריוריטי" – טוען לקוחות, אנשי קשר ופריטים.

## איך זה עובד
1. **משיכה** – כל `pollMinutes` דקות נבדקים מיילים עם PDF מ-`sinceDays` הימים האחרונים. התיבה נפתחת לקריאה בלבד; מייל שטופל לא נמשך שוב.
   אפשר גם "בדוק מיילים עכשיו", או "העלאת PDF" ידנית (לבדיקות ולהדגמה).
2. **פענוח** – טקסט וטבלאות נקראים מה-PDF (pdfplumber, מקומי). עברית שנשמרה בסדר הפוך מתוקנת אוטומטית.
   מזוהים: מס' הזמנה, תאריך הזמנה, תאריך אספקה, שם חברה (שורה עם בע"מ / Ltd), ח.פ, וטבלת הפריטים לפי כותרות העמודות
   (מק"ט / תיאור / כמות / מחיר).
3. **זיהוי לקוח** (לפי הסדר):
   1. שם החברה במסמך: זיכרון בחירות קודמות ← ח.פ (VATNUM) ← דמיון לשם הלקוח
   2. מייל השולח: זיכרון ← מייל הלקוח / איש קשר ← דומיין (לא gmail וכו')
   3. שם השולח מול אנשי קשר ושמות לקוחות
4. **זיהוי פריט**: זיכרון ← מק"ט / ברקוד (חד ערכי) ← דמיון תיאור (ודאי מעל 85% ובפער 15% מהמועמד השני).
5. **סטטוס**: *מוכנה* – לקוח וכל הפריטים זוהו; *תקועה* – מוצג מה חסר; *נקלטה* – עם מספר ההזמנה בפריוריטי; *שגיאה* – הודעת פריוריטי.
   בחירה ידנית של לקוח או פריט נשמרת בזיכרון, והזיהוי משתפר עם הזמן.

## שדות בפריוריטי (ORDERS)
| מהמסמך | שדה |
|---|---|
| לקוח שזוהה | CUSTNAME |
| תאריך הזמנה (אם אין – היום) | CURDATE |
| מס' הזמנה | REFERENCE (הזמנתכם). הזמנה עם אותו לקוח + אותה הזמנתכם לא תיפתח פעמיים |
| פרטים (אם ריק – מייל השולח) | DETAILS |
| `orders.typeCode` (אם הוגדר) | TYPECODE |
| מק"ט / כמות / תאריך אספקה (אם אין – היום + `dueDays`) | ORDERITEMS_SUBFORM: PARTNAME, TQUANT, DUEDATE |
| מחיר מהמסמך | ORDERITEMS_SUBFORM: השדה שב-`orders.priceField` (ברירת מחדל PRICE) |
| ה-PDF המקורי | EXTFILES_SUBFORM (נספחים) |

## מבנה הקוד
| קובץ | תפקיד |
|---|---|
| `mailorders/gmail.py` | משיכת מיילים (IMAP) |
| `mailorders/pdftext.py` | חילוץ טקסט וטבלאות מ-PDF – אפשר להחליף כאן ספק (OCR / PDF.co / Claude) |
| `mailorders/parsers/` | פענוח: `generic.py` כללי; תבניות לפי מקור נרשמות ב-`TEMPLATES` |
| `mailorders/matching.py` | זיהוי לקוח ופריט |
| `mailorders/priority.py` | REST API של פריוריטי |
| `mailorders/worker.py` | הצינור, הבדיקה התקופתית והשליחה |
| `mailorders/app.py`, `static/` | הדשבורד |

הנתונים נשמרים ב-`data/` (מסד SQLite, קבצי ה-PDF ומטמון פריוריטי).

## מגבלות ידועות (POC)
- PDF סרוק (תמונה) לא נקרא – יוצג כתקוע. פתרון: OCR / AI.
- הזמנה בגוף המייל בלי PDF לא נקלטת עדיין.
- הפענוח הכללי מבוסס כותרות טבלה; למקור עם מבנה חריג כותבים תבנית ב-`parsers/`.
